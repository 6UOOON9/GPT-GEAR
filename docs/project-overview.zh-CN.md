# 项目概览

[English](project-overview.md) | **简体中文**

[文档导航](README.zh-CN.md) · [快速开始](../README.zh-CN.md#快速开始) · [架构说明](architecture.zh-CN.md)

GPT-GEAR 用一个持续的 Codex 会话，在机器人仿真任务中完成“观察 → 动作 → 检查结果”的循环。它提供统一的运行、参考输入和结果记录方式，便于在不同环境中研究视觉语言模型的控制表现。

## 一次任务如何运行

1. **选择任务与初始条件。** 你指定环境、任务、seed，以及该环境需要的布局或初始化选项。
2. **检查并启动仿真。** 启动器核对源码、资源和解释器，为回合创建独立进程与输出目录。
3. **让模型观察。** 模型收到任务描述、当前相机 RGB、机器人本体状态、标定和可用工具。
4. **执行一个动作。** 模型通过 MCP 提交有界位姿增量；控制器将其转换成当前环境的原生操作。
5. **根据反馈继续。** 工具返回执行反馈和新观测，模型再决定下一步。启用参考时，在首次动作前读取一次示范。
6. **保存官方结果。** 回合结束后，由仿真环境判断任务成功，项目保存结果、录像与运行记录。

模型会话贯穿单个回合；队列中的下一个回合会启动新会话。参考轨迹用于模型理解操作，不会自动作为动作序列重放。

## 几个常见术语

| 术语 | 在本项目中的含义 |
|---|---|
| benchmark | 一套仿真任务体系，如 RoboDojo 或 LIBERO-plus，由 `--benchmark` 选择 |
| task | 具体任务；LIBERO-plus 和 LIBERO-GeoMotion 使用 `suite/task_id`，其他环境通常使用任务名 |
| episode / 回合 | 固定任务与初始条件下的一次完整评测 |
| attempt / 尝试 | 回合的一次启动执行；队列重试会生成新尝试 |
| native step / 原生步 | 后端声明的执行预算单位，不一定等于一个物理 tick |
| MCP | 模型调用 `observe`、`act` 等结构化工具的接口 |
| reference / 参考 | 评测前准备的文字、视频及可选轨迹；轨迹须搭配文字或视频 |
| smoke / 冒烟检查 | 用少量操作检查接口是否工作，不代表任务完成能力 |

## 各部分负责什么

| 部分 | 职责 |
|---|---|
| Codex 会话 | 根据可见输入规划并选择下一次工具调用 |
| MCP 与控制协议 | 校验请求、交付图片和反馈、处理重复或不确定请求 |
| 控制器 | 执行有界动作，跟踪位姿目标与预算 |
| 环境适配 | 连接仿真器的观测、动作、初始化与官方结果接口 |
| 仿真环境 | 动力学、任务规则、成功判定和原生评分 |
| 启动器与队列 | 管理进程、配置、输出目录、续跑和结果汇总 |

适配实现位于本仓库，通过指定的仿真 Python 加载外部环境，不要求修改仿真源码。工具 Python 与仿真 Python 分离，具体依赖见 [安装指南](installation.zh-CN.md)。

## 模型可以使用哪些输入

所有环境都提供当前 RGB 和机器人本体状态。相机标定用于理解视角，固定标定与腕部外参由适配层提供；不向模型提供物体真值或任务求解器。

| 可选输入 | 用途 | 可用范围 |
|---|---|---|
| 参考视频与轨迹 | 提供相似操作过程；视频可单独提供，轨迹须搭配文字或视频 | 所有支持环境 |
| 参考文字 | 提供操作步骤说明，可单独提供，也可搭配视频、轨迹或两者 | 所有支持环境 |
| 深度估计声明 | 要求模型记录基于图像的深度估计，不提供测量真值 | 按运行选项启用 |
| 测量深度 | 查询已保存 RGB 对应像素的深度与反投影位置 | GR1 |
| 触觉图像 / 合力 | 为接触操作提供额外观测 | UniVTAC |

GR1 默认启用测量深度，其他环境默认要求深度估计声明；这两种模式不能同时开启。参考文件需要提前准备，只有视频转文字的生成过程由本项目提供，见 [参考输入指南](reference-protocol.zh-CN.md)。

## 如何理解评测结果

任务成功以环境官方判定为准。控制器到达末端目标、工具调用执行成功、模型调用 `finish`，都不能单独证明任务成功。

汇总区分有效成功、有效任务失败、无效样本和运行错误。发布结果时，应说明任务与初始化条件、模型和输入配置，并报告无效与中断数量；不同环境的原始评分分别统计。详见 [结果指南](results.zh-CN.md)。
